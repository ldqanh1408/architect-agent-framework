# Container view — InvoiceFlow

## Question and audience

"Which runnable pieces exist, and which one calls which?" Read by a new engineer on their first day and by
anyone sizing the blast radius of a change.

## Source

Generated from `workspace-plan.yml` and the `source-map.yml` of each module. Container ids match
`02-domains/00-overview/domains-index.md`; nothing here is drawn by hand.

## Elements and relations

- `web-app` (browser SPA) → `api-gateway`: HTTPS, bearer token.
- `api-gateway` → `20-invoicing`: internal gRPC.
- `20-invoicing` → `10-payments-adapter`: internal gRPC, synchronous, 3 s timeout.
- `20-invoicing` → `outbox` (PostgreSQL): same transaction as the status write.
- `30-notifications` ← `outbox`: polls, at-least-once.

An arrow means "initiates a call to". It does not mean data flows only that way.

## Omissions

Deployment topology, replica counts, and the observability stack are deliberately absent — they belong to
`04-deployment/`. Showing them here made the picture unreadable at eight containers.

## Freshness

Regenerated by `GATE-TREE-PLAN-RENDER` on every plan change; the gate fails if this page differs from a fresh
render, so a stale drawing cannot be committed.
