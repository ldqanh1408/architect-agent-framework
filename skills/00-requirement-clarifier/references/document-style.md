# Write clear technical English

Use short sentences, familiar words and one instruction at a time. Keep terms consistent.
Apply `aaf-ste80-v1` and the workspace's versioned `language.glossary`. Target at least 80% of eligible prose sentences passing every applicable rule, both per document and across the candidate. This is a project metric; it is not ASD-STE100 certification.

Preserve IDs, actors, values, units, links, literals, source quotes, normative force, negation, scope and UNKNOWN. Keep writer, style and meaning assessments separate. The host author writes; Jev evaluates. Use `architect_candidate_review` or `architect_language_review` on the exact candidate. Read rule evidence and unknowns; missing dictionary authority remains UNKNOWN in the denominator. Three heuristics run locally; Jev assesses all eight project rules. Independent standard mapping and real model quality remain unverified until supplied.

Use `architect_language_repair` for a targeted grant-checked proposal, then review its returned candidate again. At most two repair attempts per document lineage share the original candidate's budget. Keep the last fact-safe draft if review fails. Present unresolved wording and meaning for signed human review. A callback or model verdict never grants qualification, acceptance or publication.
