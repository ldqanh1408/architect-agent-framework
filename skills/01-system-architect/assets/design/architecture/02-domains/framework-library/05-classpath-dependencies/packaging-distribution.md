## 2. JAR Layout

```text
example-starter-${version}.jar
├── META-INF/
│   ├── MANIFEST.MF
│   ├── spring/
│   │   └── org.springframework.boot.autoconfigure.AutoConfiguration.imports
│   ├── example-starter/
│   │   └── providers.json
│   └── LICENSE
└── com/example/starter/…                    # public + internal classes
```

Never ship consumer-only test fixtures under the main JAR — publish `-test` as a separate artifact.

## 3. Publishing Pipeline

| Stage | Tooling | Output |
|---|---|---|
| Build | Maven `verify` | JAR + sources + javadoc |
| Sign | GPG detached signature | `.asc` files |
| Stage | `mvn deploy` to staging repo | staged bundle |
| Release | Sonatype OSSRH promote / GitHub Packages | Maven Central / GH Packages |
| Attest | SLSA provenance | `.intoto.jsonl` |

## 4. Signing & Provenance

- GPG signature is mandatory for every artifact.
- SLSA-Level-3 provenance is generated by the reusable release workflow.
- Consumers can verify with `gpg --verify example-starter-${version}.jar.asc example-starter-${version}.jar`.

## 5. Guardrails and Defaults

| Guardrail | Default | Rationale |
|---|---|---|
| SNAPSHOTs never leave `main` | Enforced by release job | SNAPSHOT in Central would be unreproducible |
| Every artifact has sources + javadoc | Enforced by Maven Central rules | Consumers need source-jump in IDE |
| Group ID is registered under the framework owner | `com.example` | Prevents supply-chain squatting |
